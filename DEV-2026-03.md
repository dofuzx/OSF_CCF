## **Summary of Deviation**

During the M2a experiment run on a 32 GB memory machine, two consecutive OOM (out-of-memory) incidents occurred, causing the experimental analysis to be unable to continue.

## Details of the Deviation

1. Original workflow design: The M2a experiment originally planned to load the raw expression matrices of all 39 samples to be analyzed into memory, merge them, and then process them together; this approach imposed high memory requirements.
2. Actual runtime issue: When running the M2a experiment on a 32 GB memory machine, OOM was triggered twice consecutively, the analysis was interrupted, and the original workflow could not continue.
3. Cause: The original design kept the raw matrices of all 39 samples resident in memory before merging, causing peak memory to exceed the capacity of the 32 GB machine.

## Impact Assessment

1.Impact on scientific conclusions: None. This deviation only involves adjustments to operational resources and workflow implementation. The QC thresholds, doublet detection logic, and myeloid lineage determination logic are unchanged, and the analysis objectives and scientific conclusions are not changed.
2.Impact on experimental results: After the adjustment, it is necessary to ensure that the singlet matrices output by per-sample processing and the subsequent merged results remain consistent with the original design in terms of analysis criteria. Parameter configurations, run logs, and code versions should be retained for traceability.
3.Impact on operational resources: Per-sample streaming processing significantly reduces peak memory and prevents the 32 GB machine from experiencing OOM again due to all matrices being kept resident in memory. It may increase runtime and disk I/O to some extent, but does not affect the validity of the analysis.
4.Impact on data version: Because a full rerun was performed after the two OOM incidents, the results of all seven datasets generated by the complete rerun under the adjusted workflow should be regarded as the final analysis version, and the rerun time, code version, and parameter configurations should be recorded.

## Resolution

1. Adjust the M2a experimental analysis workflow to per-sample streaming processing: read → QC → scDblFinder → retain only singlet matrices, so as to reduce the memory requirements and peak memory of the analysis process.
2. Fix and record the code version, QC thresholds, scDblFinder parameters, and myeloid lineage determination rules of the adjusted workflow to ensure consistency with the experimental design requirements.
3. Use the adjusted workflow to fully rerun all seven datasets and retain complete run logs.
